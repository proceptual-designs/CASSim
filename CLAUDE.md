## Decisions already made (do not re-litigate)
- Repo lives at `C:\dev\CASSim`, outside OneDrive. The virtualenv is the in-project `.venv` (uv default; do not set `UV_PROJECT_ENVIRONMENT`). Commit and push to a Git remote often.
- Correctness is judged by **symbolic/numeric equality**, not TI's exact output text. Maths is rendered from LaTeX.
- Python scripts in the app are sandboxed in the browser but must prompt before running.
- Geometry page is out of initial scope.
- Python 3.14 (matches Pyodide 314.0.7). Tooling: **uv, Ruff, Ty, Git, pytest, Hypothesis, Playwright**.
- Core engine (`src/cassim/core`) is pure Python and must never import Flet. SymPy is touched only inside `core/compat/sympy_adapter.py`. Core is fully typed and passes Ty strict.
- TI syntax is parsed with a real tokenizer + Pratt parser, not regexes (see `spikes/ti_eval_spike.py` for why).
- Canonical text is Unicode: `e` is a variable, `ⅇ` is Euler's constant, `ᴇ` is the exponent marker. ASCII is only a REPL spelling (`to_ascii` in `core/format.py`).
  - **Do not overwrite or "normalise" these symbol conventions** (reviewed and confirmed 2026-11-01; see `docs/decisions/0007-parser-grammar.md` and `to_ascii`). Canonical Unicode forms: `ⅇ` Euler's constant, `ⅈ` imaginary unit, `ᴇ` exponent marker (`3.14ᴇ6`), `π`, `∞`, `ᵀ` (U+1D40), `ʳ`, `ᵍ` (U+1D4D, a lowercase superscript g, ASCII `@g`; not the uppercase `ᴳ`), `°`, `∠`, `▶`. Plain `e`, `i`, `E` are ordinary variables, so `2e3` is `2*e3`. Typed (input) spellings in corpus `in:` lines are TI's ASCII ones: `@e`, `@i`, `@E`, `@t`, `@r`, `@g`, `@d`, `@<`, `@>`, `pi`, `infinity`; `out:` lines use the Unicode forms. Never replace `ⅇ`/`ᴇ` with `e`/`E` in outputs, and never replace `@>` with `▶` in inputs.
- Statistics must follow the TI/school convention, not numpy: quartiles are the median of the lower and upper halves (median excluded when n is odd), e.g. Q1 of {1,4,9,16,25,36,49,64} is 6.5 and Q3 is 42.5 (numpy's default gives 7.75 and 39.25). Implement it directly; do not call `numpy.percentile`/`quantile`. Sample sd uses n-1 (`sx`), population uses n (`σx`).
- Data pages and graphs (decision 0031, 2026-11-13): within a Problem the engine's variables are the only copy of the data and every page is a view of them; the document stores definitions and view state, not values. Each page's model and cached scene are kept, and a switch rebuilds the controls from them without waiting for the engine (keeping hidden Flet controls alive is slower: spike A). Pages can split into two panes. SciPy and NumPy are not shipped (statistics are pure Python and mpmath; SciPy only checks them in tests). The General Maths categorical charts (dot chart, bar chart, pie chart) are Must.
- Other simulator behaviours to match (details in `docs/testing/TESTING.md` section 14): Approximate mode shows decimals inside symbolic results (`3.·x^2`); Float 3 / Fix 2 switch to `ᴇ` notation for very small or large values (`5.00ᴇ-3`); `1/0` and `ln(0)` give `undef`, not errors; undefined variables echo unchanged; `int(-2.5)` = -3 (floor); `sinh⁻¹(1)` stays unevaluated in Auto mode; spreadsheet whole-column references are `a[]`; Graphs coordinates label to 2 dp and Integral accepts typed bounds.
- Pseudocode (M7b, reviewed 2026-11-06; see `docs/decisions/0020` and `0021`): Euler's `e` is on by default; run limits are 1,000 passes per loop, 20,000 trace steps and recursion depth 100; `[ ]` always makes a list and only `( )` groups; `ax` is not split into a*x in the default and strict syntax presets (it is in the vcaa and author presets). The syntax file (`runtime/pseudocode/syntax.py`) drives the lexer and parser.
- IP boundary and clean room (`docs/decisions/0028`, NFR-LEG-008, NFR-LEG-009): copy behaviour, structure and vocabulary (names, syntax, menus and numbering, key positions, settings), never expression or code (artwork, fonts, help or Reference Guide prose, ROM, data tables). Learn behaviour only by using TI's software; never decompile or inspect its binaries. Paraphrase `references/`, never paste it into `src/`. Short functional labels may match the device. Open/Save are `.cassim.json` only; `.tns`, if ever built, goes under Import/Export (FR-DOC-006).
- Library UDFs (`mm_`, `sm_`, `gm_`) are `.tns` and not loadable. Port them to native Python later (M5). LazyMath is Unlicense, so porting is permitted; record the check in `docs/decisions/` first.
- Sites, bundles and publishing (2026-11-13; PLAN.md sections 14 and 15, README "Publishing"):
  - `cassim-app` (stable) and `cassim-calc` (testing) are the all-in-one app with every built device; single-device bundles get their own stable-only sites (`cassim-tin`, `cassim-pseudo`, `cassim-cp`, `cassim-prime`) as they are built. `cassim-wiki` is the help site and lists the sites.
  - Each device is a plug-in package (`devices/nspire`, `classpad`, `pseudocode`, `prime`: long ids in code, short names for bundles and sites) that never imports another device; device UIs are separate from the shell. Pseudocode (the Code view) is a device with its own site (Q23 revised).
  - A merge to `main` deploys testing and the help pages; a GitHub release deploys stable. Never deploy stable by hand with wrangler unless Simon asks.
- Decisions from the SRS review (2026-11-02; see `docs/SRS.md`):

  - No fixed performance or size budgets: cold start and download size are measured and reported. Cancel must take effect within 1 s.

## Conventions
- Small commits, conventional commit messages. Every behaviour change ships with a test; cite the SRS requirement ID in the test where one applies. Design docs go in `docs/design/` (SDD set listed in SRS appendix A). Fix lint and type errors rather than suppressing them.
- **No inline Python edits through a Bash heredoc** (`python - <<'EOF'`) when the text has backslashes: LaTeX such as `\boldsymbol`, Windows paths such as `C:\dev`, or regexes. Python reads them as string escapes, so `\b` becomes a backspace (ruff PLE2510) and `\d` makes the search text fail to match. Use the Edit tool for exact changes. For scripted edits, write a `.py` file to the scratchpad with raw strings (`r"..."`), pass it the target path, and open files with `newline=""` so Windows does not write CRLF. Heredocs are fine for text with no backslashes (commit messages, PR bodies).
- Known failing corpus cases are `xfail(strict=True)` with a reason.
- Branch protection (GitHub ruleset `protect-main`; see the 2026-11-09 chat). Never push to `main` directly: work on a branch in its own worktree and open a PR. Merge with `gh pr merge --merge` (merge commits are kept on purpose; linear history is **not** required, so do not rebase or squash unless asked). Force pushes to `main` and deleting `main` are blocked. CI has one job, `check` (ruff, ty, pytest), and it must be green before merge; if it fails, fix the cause and push again rather than bypassing. Required approvals are 0 (Simon is the only reviewer, and Claude commits under Simon's account). The admin bypass is Simon's escape hatch: never use it, and never edit or delete the ruleset, without being asked. Delete the branch and worktree after merge.
- Keep the docs and code in step. When you add, move or remove a package under `src/cassim/`, update the architecture map in `PLAN.md` section 3 in the same commit (`tests/test_architecture.py` checks it, and the `[placeholder]` tags). When you touch code listed in the PLAN.md section 12 follow-up table and its trigger is met, do that cleanup then and delete the row.
- Never use TI logos, artwork or ROM content. The product name is CASSim.
- Reference material is in `references/` (Reference Guide, shortcuts, VCE teacher resource books, LazyMath UDF guides and libraries). Do not edit it.
